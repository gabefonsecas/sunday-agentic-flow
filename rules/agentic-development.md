# Agentic development rules

- Inspect repository instructions before planning or editing.
- Start the complete managed workflow for every development request.
- Never require skill names or orchestration prompts from users.
- Convert vague requests into explicit, testable acceptance criteria.
- Keep Friday cards synchronized with actual execution state.
- Require evidence before marking work complete.
- Never push or publish a PR before relevant checks pass.
- Select `main` or `homolog` from task intent and repository evidence.
- Stop when branch targets or destructive external actions remain ambiguous.
- Route work automatically across host-provided remote model tiers.
- Invoke separate specialists for all four routing phases.
- Record requested and observed routing evidence.
- Assign the token-authenticated Friday user before implementation.
- Let the primary agent own final synthesis and external actions.
- Use independent subagents for analysis and verification when available.
